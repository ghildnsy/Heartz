A.​Ringkasan Eksekutif 
Keterbatasan akses dan tingginya biaya terapi wicara profesional menjadi 
hambatan utama bagi penyandang disabilitas rungu (Tuli) untuk melatih 
artikulasi lisan secara konsisten. Pada terapi konvensional, teman Tuli sangat 
mengandalkan umpan balik visual untuk meniru bentuk mulut terapis. Namun, 
ketiadaan indra pendengaran membuat mereka kesulitan memvalidasi apakah 
getaran pita suara dan bentuk rahang mereka telah menghasilkan frekuensi 
suara yang tepat, khususnya saat merangkai konsonan dan vokal menjadi suku 
kata dasar.  
Oleh karena itu, proyek Heartz hadir sebagai sebuah painkiller dalam 
bentuk Sistem Visualisasi Artikulasi berbasis audio. Hal ini memunculkan 
Problem Statement, diantaranya bagaimana (How) kita bisa menyediakan alat 
terapi wicara mandiri yang terjangkau bagi Sahabat Tuli (Who), di lingkungan 
rumah (Where), kapan saja mereka butuhkan (When), untuk membantu mereka 
menyesuaikan volume suara dan artikulasi secara akurat (What), guna 
meningkatkan kepercayaan diri dalam berkomunikasi (Why?). 
 

 
Research Question utama dalam proyek ini adalah Bagaimana arsitektur 
model Convolutional Neural Network (CNN) 2D dapat mengklasifikasikan fonem 
vokal dan suku kata dasar bahasa Indonesia secara presisi dengan tingkat 
akurasi 85% berdasarkan ekstraksi fitur visual Mel-Spectrogram, guna 
memberikan feedback korektif secara real-time. 
Tim kami memilih proyek ini karena Heartz menawarkan inovasi yang 
tepat guna. Sistem ini murni menganalisis gelombang frekuensi suara fisik 
pengguna tanpa melibatkan pelacakan wajah (Face Tracking) berbasis kamera. 
Jika pelafalan suku kata melenceng dari target frekuensi, AI akan mendiagnosis 
tingkat kesalahannya dan menampilkan panduan animasi visual pada layar. 
Dengan demikian, platform ini memberdayakan penyandang disabilitas rungu 
untuk melakukan repetisi latihan wicara mandiri dengan validasi diagnostik yang 
akurat serta privasi pengguna yang tetap terjaga. 
 
B.​Cakupan Proyek dan Hasil Kerja 
Cakupan proyek Heartz difokuskan pada penyelesaian Minimum Viable 
Product (MVP) dalam durasi pengerjaan yang terukur, yakni 4-5 minggu. Untuk 
memastikan model AI mencapai tingkat akurasi yang diwajibkan (di atas 85%), 
batasan sistem secara spesifik diarahkan pada pemrosesan data audio murni 
(audio-only) tanpa melibatkan pelacakan wajah (Face Tracking) berbasis kamera. 
Model AI akan dilatih secara khusus untuk mengklasifikasikan 20 kelas 
target pelafalan, yang mencakup 5 fonem vokal dasar (A, I, U, E, O) dan 15 suku 
kata berbasis konsonan bilabial/bibir (Ba, Bi, Bu, Be, Bo, Pa, Pi, Pu, Pe, Po, Ma, 
Mi, Mu, Me, Mo). Konsonan bilabial dipilih sebagai langkah awal karena bentuk 
fisik artikulasinya paling mudah dipelajari oleh penyandang Tuli.

E.​Sumber Daya Proyek 
Bahasa Pemrograman, Framework, dan Module Bundler untuk 
Front-End 
Untuk membangun Sistem Visualisasi Artikulasi yang responsif, kami 
menggunakan JavaScript (ES6+) dengan React.js sebagai framework front-end. 
React memungkinkan pengembangan komponen UI yang efisien, khususnya 
integrasi Web Audio API untuk menangkap frekuensi suara via mikrofon 
peramban secara real-time. Vite dipilih sebagai module bundler karena 
kecepatan hot-reload yang esensial untuk prototyping cepat. Tailwind CSS 
digunakan untuk membangun layout responsif dan merancang animasi 
feedback visual (diagnosis artikulasi) yang ramah bagi penyandang disabilitas 
rungu. Axios digunakan sebagai HTTP client untuk mengirim data audio ke 
Back-End API secara efisien dengan dukungan interceptor dan penanganan

Pengembangan Model Deep Learning 
Model utama proyek ini dibangun menggunakan TensorFlow Functional 
API dengan arsitektur murni Convolutional Neural Network (CNN) 2D untuk 
klasifikasi 20 kelas suku kata target. Kami tidak menggunakan model sekuensial 
(seperti RNN/LSTM) demi menjaga performa komputasi pada durasi audio

Inference Model dan REST API Mandiri untuk AI 
Model yang diekspor dibungkus dalam REST API mandiri menggunakan 
FastAPI (Python). FastAPI dipilih karena dokumentasi otomatisnya (Swagger) dan 
kemudahan integrasi beban komputasi Machine Learning. Proses inference ini 
menerima input audio (.wav), mengekstraksi fiturnya, dan mengembalikan 
respons JSON berisi prediksi kelas suku kata. API ini di-deploy secara terpisah di 
layanan seperti Google Cloud Run. Sebagai pendukung sekunder, kami 
mengintegrasikan Google Gemini API untuk menghasilkan pesan penutup atau 
afirmasi teks yang adaptif guna memotivasi pengguna setelah sesi latihan 
selesai. 
Dataset, Pengumpulan Data, dan EDA 
Dataset utama tidak menggunakan model pre-trained bahasa asing, 
melainkan hasil Data Gathering mandiri secara spesifik untuk pelafalan dalam 
bahasa Indonesia. Pengumpulan data dilakukan melalui ekstraksi audio dari 
video edukasi di YouTube (berlisensi publik) untuk 20 kelas suku kata target 
(vokal dasar dan konsonan bilabial). Pemrosesan end-to-end menggunakan 
Python (Pandas, NumPy, Librosa) mencakup pemangkasan senyap, denoising, 
dan penyeragaman sample rate menjadi 16 kHz. Exploratory Data Analysis (EDA) 
divisualisasikan dengan Matplotlib dan Seaborn. Seluruh wawasan analitik, 
seperti distribusi fitur akustik, diintegrasikan ke dalam dashboard interaktif 
Streamlit dan di-deploy ke Streamlit Cloud.

F.​ Rencana Manajemen Risiko dan Isu 
Untuk memastikan kelancaran pengerjaan Minimum Viable Product (MVP) 
dalam

mengimplementasikan 
kerangka 
manajemen risiko berbasis operasional dan teknis. Berikut adalah hasil 
identifikasi faktor-faktor yang berpotensi menghambat proyek beserta langkah 
mitigasinya : 
1.​ Risiko Kualitas Data (Kebisingan/Noise) 
●​ Isu: Pengumpulan dataset audio (khususnya melalui scraping) rentan 
memiliki noise latar (suara angin, kendaraan, atau musik) yang bervariasi. 
Hal ini dapat menurunkan akurasi model CNN 2D. 
●​ Mitigasi: Tim Data Science menetapkan standar pembersihan data yang 
ketat menggunakan teknik denoising (seperti spectral gating). Selain itu, 
tim melakukan augmentasi data dengan noise injection dan pitch shifting 
(Feature Engineering) saat training, agar model lebih tahan banting 
(robust) terhadap variasi mikrofon pengguna di dunia nyata. 
2.​ Risiko Kemacetan Kerja (Bottleneck Integrasi) 
●​ Isu: Tim Full-Stack Web berpotensi tertunda pengerjaannya jika harus 
menunggu model AI dan Back-End selesai dilatih dan di-deploy secara 
utuh pada minggu ke-3. 
●​ Mitigasi: Mengimplementasikan Mock API menggunakan data dummy 
berupa respons JSON statis sejak minggu ke-1. Dengan cara ini, tim 
 

 
Front-End dapat mulai merancang logika UI/UX dan animasi feedback 
visual tanpa harus menunggu server inference AI benar-benar selesai. 
3.​ Risiko Kinerja Sistem (Latensi Inference) 
●​ Isu: Pengiriman file audio berekstensi .wav secara konstan dari klien ke 
server berpotensi menyebabkan penundaan (lag) dalam memunculkan 
feedback diagnosis artikulasi. 
●​ Mitigasi: Menerapkan pembatasan durasi perekaman maksimal (1-2 detik 
per suku kata) untuk meminimalkan ukuran payload. Selain itu, 
antarmuka web akan dilengkapi dengan animasi loading state (seperti 
visualisasi gelombang suara) agar pengguna menyadari bahwa sistem 
sedang memproses data, sehingga User Experience (UX) tetap terjaga. 
4.​ Risiko Overfitting pada Model Deep Learning 
●​ Isu: Mengingat dataset pelafalan fonem Indonesia sangat spesifik, model 
berisiko hanya menghafal data latih dan gagal memprediksi suara baru 
(overfitting). 
●​ Mitigasi: Tim AI Engineering akan menerapkan teknik Dropout pada 
arsitektur CNN 2D serta menggunakan Custom Callback berupa Early 
Stopping. Jika validation loss tidak membaik dalam beberapa epoch, 
proses pelatihan akan otomatis dihentikan untuk menyimpan bobot 
(weights) yang paling optimal. 
5.​ Risiko Stabilitas Aplikasi (Crash pada Fitur Utama) 
●​ Isu: 
Integrasi 
antara 
Web 
Audio 
API 
(Front-End), 
REST 
API 
Node.js/Express.js (Back-End), dan Inference FastAPI (AI) melibatkan 
banyak titik kegagalan. Kesalahan penanganan respons API, format audio 
yang tidak sesuai, atau koneksi jaringan yang terputus berpotensi 
menyebabkan crash atau UI tidak responsif pada fitur utama klasifikasi 
suku kata. 
●​ Mitigasi: Tim Full-Stack Web akan mengimplementasikan error handling 
yang komprehensif di setiap lapisan: try-catch di sisi klien (React.js), 
validasi format audio sebelum dikirim via Axios, serta respons error yang 
informatif dari Express.js ke klien. Selain itu, pengujian end-to-end 
terhadap alur perekaman audio hingga tampilnya feedback visual akan 
dilakukan secara manual pada Minggu 4, mencakup validasi setiap 
endpoint menggunakan Postman dan browser testing untuk skenario 
 

 
koneksi terputus, guna memastikan fitur utama berjalan stabil tanpa 
crash.
